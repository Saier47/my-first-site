## 怎么跑起来

### 方式一：起本地服务（推荐，截图/验收用这个）

在**项目文件夹里**打开终端，执行：

```bash
python -m http.server 8000 --bind 127.0.0.1
```

然后在浏览器打开：

```
http://localhost:8000
```

看到页面就成功了。想停掉服务：回到终端按 `Ctrl + C`。

> 为什么不用双击打开：双击走的是 `file://` 协议，浏览器对本地文件有限制，
> 而且没法在地址栏里看到 `localhost`。起服务是最接近「真的在服务器上跑」的方式。
> 本项目是纯静态页面，所以一个 Python 自带的静态服务器就够，不需要装任何东西。

### 方式二：直接双击 `index.html`

也能用（纯静态页面没有跨域问题），但地址栏不是 `localhost`，且部分浏览器对
`file://` 下的本地存储有限制。**验收和截图请用方式一。**

## 页面怎么走（Day 13）

一共 **3 个视图**，靠**地址**切换 —— 改地址栏里 `#` 后面那段，页面不会重新加载。

```
一级：底部导航（2 个入口 —— PRD 第 2.2 节第 2 条要求「不许有第 3 个」）
 ├── #/week     一周视图（打开默认在这）
 └── #/courses  清单页（课程 + DDL + 筛选）

二级（从一周视图里「今天」那一列的列头点进去）
 └── #/today    今天视图
```

| 地址 | 看到什么 |
| --- | --- |
| `#/week` 或什么都不写 | 一周视图 —— 这周的固定课和 DDL 叠在 7 列时间轴上 |
| `#/courses` | 清单页 —— 课程按星期分组、DDL 按截止时间排 |
| `#/courses?q=高数` | 清单页 + 筛选「高数」（筛选词也写进地址，能分享、能后退） |
| `#/today` | 今天视图 —— 今天几节课、几个 DDL 到期、有没有欠着的 |

**为什么「今天」放在二级、不占底部导航？**
"底部只有 2 个入口"是 PRD 用来验证"没偷偷加回校园社交、空教室"的防线（打开页面数一数就知道）。
所以第三个视图做成**点进去的下一层**，靠面包屑「← 这一周」回来 —— 底部导航仍然是 2 个。

**顺带买到的好处**：地址驱动意味着浏览器**后退键能用**、刷新停在原地、链接能直接分享。

### 四种状态

每个视图都有四种样子。数据没到手时，切到哪个视图看到的都一样（不会出现"一周视图在转圈、清单页一片空白"）。

| 状态 | 怎么看 |
| --- | --- |
| 正常 | 直接打开 |
| 加载中 | 打开的一瞬间（约 0.6 秒）就是 |
| 空 | 地址加 `?src=empty`，如 `index.html?src=empty#/week` |
| 出错 | 地址加 `?src=error`（带「重试一次」按钮） |

> `?src=...` 要写在 `#` **前面**，这样切视图时它不会丢。
> 这是**验收通道**，只是把已有的 mock 开关挪到地址栏上，数据没有变。

## 真数据 / 假数据（Day 8 加 · 2026-09-30 改了默认值）

**默认走真数据** —— 从你这台电脑的浏览器里读（localStorage）。

> ⚠️ **2026-09-30 改的默认值。** 以前默认开着假数据，后果是：
> **用户录的课只进内存、一刷新就没**，而保存时还会正常弹出「✓ 已保存」。
> 一个学生打开网页、录完自己的课、关掉再打开 —— 课全没了。
> 详见 `usability-checkup.md`。
> 现在假数据默认**关**，打开网页看到的就是你自己的数据。

假数据是拿来**演示 / 截图 / 看四种页面状态**的。用**地址参数**开启，不用改源码：

| 地址 | 看到什么 |
| --- | --- |
| 直接打开（不加参数） | **你自己的真实数据** |
| `?src=normal` | 演示用的**假数据**（内容固定，换台电脑打开也一样） |
| `?src=empty` | **空状态**（引导语 + 添加按钮） |
| `?src=error` | **出错状态**（说明 + 重试按钮） |

例：`index.html?src=normal#/week`

> `?src=...` 要写在 `#` **前面**，这样切换视图时它不会丢。
> 「加载中」不用参数 —— 打开的一瞬间（约 0.6 秒）就是骨架屏。

`app.js` 一个字都不用改 —— 这就是「数据源可替换」的意思。
（`check-persist.js` 专门盯着"默认真数据"这条，谁要是把开关改回去，测试立刻变红。）

## 数据存在哪

存在**你自己这台设备**的浏览器里（localStorage），**不上传任何服务器**。

存储键名：`mfs:courses`（课程）、`mfs:ddls`（DDL）。

**代价（本期明知并接受）**：
- 清空浏览器数据 / 用无痕模式 → 数据会丢；
- 换设备、换浏览器 → 数据不通用。

这两条等接入云数据库之后解决。

### 云数据库能读也能写了，但前端**还没接**（Day 18 现状）

Day 16 建表灌种子 · Day 17 让云函数能**读** · Day 18 让云函数能**写**。
但**网页目前读写的仍然是浏览器里的 localStorage**。

这不是没做完，是**故意分开的**：建表(16) → 读接口(17) → 写接口(18) → 改前端(19)。
到今天为止，`store.js` 还没动过 —— 函数签名一个都不变，`app.js` 依旧一行不改
（这就是 Day 5 那条铁律买来的好处）。

| | 现在（Day 18） | 接上之后 |

不做：教务系统导入、成绩/空教室/校园社交、账号与云同步、打包成 App、

## 以后要做（Backlog）

不属当前任务范围、但已确认有价值和方案的事，记在这里，等对应阶段开工时直接接上。

### 1. DDL 勾选改成「点整行」（第 3 周）

**现状**：勾选框视觉上只有 18×18px（Day 9 已把**热区**撑到 44×44px 达标）。
**要改**：点整行都能切换完成状态，热区从 18px 变成整行几百 px。
**为什么**：核心场景是「晚上躺床上看明天有什么」——单手躺着去瞄准 18px 方框是最难的姿势。
点不中的后果是用户开始怀疑自己，而不是报错。**这类问题不产生报错，只产生流失。**
**坑**：行内还有「编辑 / 删除」按钮，事件挪到整行后点它们不能同时打勾。
**和谁一起做**：第 3 周，与「手机真机实测」一起 —— 必须真机摸过才验证得了。
详见 `PRD.md` 第 10.1 节。

### 2. `check-day8.js` 的日期断言会随日期漂移

**现状**：脚本里几处期望值写的是绝对日期（"本周四那条应该渲染出来"），
但假数据是**按运行时现算**的。今天（9/26 周六）跑，就会有 3 项失败，
而它们和代码改动无关。
**要改**：把期望值也改成相对计算，或者把"今天"注入成固定值。
**为什么**：一个会自己变红的测试，久了你就不看它了 —— 那它就白写了。
**什么时候**：下次动 `check-day8.js` 时顺手修。

### 3. 删除的反馈（第 3 周）

**现状**：删除有确认弹窗（防止误删），但**删完之后没有结果态** ——
记录消失就是唯一的信号。而"消失"和"没删掉"在视觉上可以很像。
**要改**：复用 Day 11 的 `showToast()`，删完提示「已删除：XXX」。
**为什么**：Day 11 已经证明"过程态 + 结果态"是保存交互的必需品，
删除是同一个模式（也是一个 600ms 的异步写操作），不该有两套标准。
**坑**：删除是不可逆操作，提示条要做成"可以点撤销"还是纯告知，需要先定
（本期不做撤销功能，所以先做纯告知）。
