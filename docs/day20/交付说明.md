## 4. 🔑 今天要掌握的那句话（答案）

> **跨域被拦时，请求其实已经打到服务器了。**
> 浏览器是看到响应里缺 `Access-Control-Allow-Origin` 才把结果掐掉的。

**怎么认出问题出在哪 —— 看后端日志：**

| 后端日志 | 结论 |
|---|---|
| **有**这次请求（有 requestId） | **跨域问题** → 查/补响应头 |
| **没有**这次请求 | 根本不是跨域 → 请求没发出去 |

### 今天的实情：跨域**本来就通了**，但不是我们写的

实测响应头：

```
server: tcbgw
access-control-allow-origin: https://my-first-site-...tcloudbaseapp.com
```

`server: tcbgw` = **腾讯云网关自己加的**。函数代码里一行 CORS 都没有（已 grep 确认）。

**所以决定不加** —— 网关回显的是精确 `Origin`，函数里再写一份
`Access-Control-Allow-Origin: *` 会让响应出现**两个**该头，按规范属**无效响应**，
反而把已经通的跨域弄坏。

## 5. ⚠️ 一个要记的坑：`tcb hosting deploy` 不能传 `/`

**现象**：上传报 `√ Successfully uploaded 8 file(s)`、退出码 0，
但文件被传到 `D:/第一学期.../PortableGit/` 这种 Git 安装目录里，**首页根本没更新**。

**根因**：`tcb.cmd` 经 Git Bash shim 启动，`/` 参数被 MSYS 路径转换吃掉了。
（连不带 `/` 的 `manifest.json` 都被塞进那个路径，因为**云端目标目录**这个参数被翻译了。）

**修法**：**不传路径参数**，让它用默认根目录：

```bash
# ❌ 会歪
tcb hosting deploy .deploy-tmp / -e <envId>
# ✅ 干净
tcb hosting deploy .deploy-tmp    -e <envId>
```

> 这是「命令跑了 ≠ 命令生效了」的第三次复现（前两次：`git push` 静默失败、
> `run-sql.sh` 吞错误）。**唯一可靠的办法是从另一个角度独立查一遍。**

## 11. 🔴 交付后发现的严重 bug 与修复（本日最重要的教训）

**现象**：用户打开公网页面，**永远停在骨架屏**，只有「数据同步于 15:58」显示出来了。

**真凶**（用真浏览器抓到控制台）：
```
ReferenceError: ddls is not defined
    at render (app.js:1141:19)
```

**根因**：加 `renderSyncNote()` 时，我的编辑**误删了两行**：
```js
const courses = (usingMock() && mockSource() === 'empty') ? [] : data.courses;
const ddls    = (usingMock() && mockSource() === 'empty') ? [] : data.ddls;
```
于是 `ddls.filter(...)` 直接抛错，**渲染整条链断掉**。

### 为什么三层自检没抓到（这是关键）

`check-day20.js` 的 33 项**全是静态检查**：
- A 接口层：接口能不能通 ✅
- B 源码层：文件里有没有 `API_BASE`、正则匹配 `fetch(` ✅
- C 部署层：线上文件字节和本地一不一样 ✅

**没有一条真的执行过 `render()`。**
→ 文件传对了、接口通了、字符串都在 —— **但代码跑不起来**。

> 🔑 **「文件传对了」≠「代码能跑」。**
> 要看"能不能跑"，只有一条路：**真的跑一遍**。

### 修复与补救

1. **补回两行**，并在那里留了警告注释（`⚠️ 这两行不能删`）
2. **新建 `check-day20-render.js`（11 项）** —— 真正的运行时自检：
   搭最小 DOM → 真加载 `store.js` + `app.js` → **真调云端接口** → **真执行 `render()`**
   → 检查 DOM 里有没有渲染出 7 个 day 块、有没有课程名、有没有残留骨架屏
3. **带自证环节**：脚本会把 `courses`/`ddls` 声明删掉重跑一遍，
   **必须报出 `ddls is not defined` 才算这个脚本有效** —— 造一个已知的坏版本验证探测器本身能工作
4. **用真浏览器复验**：控制台零报错、页面完整渲染（周一至周日七列 + 4 条过期 DDL）

### 顺便学到的：真浏览器怎么用

本日装上了 `agent-browser`（自带 Chromium），拿到了本机**唯一可用的浏览器自动化能力**
（Edge 无头截图 Day 19 已彻底失效）。关键用法：
- `agent-browser open <url>` → 打开
- `agent-browser console` → **拿控制台报错**（就是这条抓到 `ddls is not defined`）
- `agent-browser read` → 拿渲染后的文本
- `agent-browser eval <js>` → 执行 JS

⚠️ `open` 会占住前台不返回 → 用 `nohup ... &` 或 `timeout` 包住；
`ref=e1` 每次快照都会变，别跨命令引用。

### 复盘：这次该怎么做才对

**改 `render()` 这种"总调度函数"时，改完必须立刻在一个对象上验证它还能跑通**，
而不是等到三层静态检查全绿就以为没事了。

我已经知道 `render()` 是四条数据的汇聚点（`renderOverdue` / `renderWeek` / `renderToday` / `applyFilter`），
动它之前应该跑一次运行时检查 —— **静态检查是"有没有写"，运行时检查是"能不能用"，两者不能互相替代**。
