这份提纲只有一个任务：让别人 3 分钟听懂「这是什么、怎么用、我是怎么做出来的、我凭什么说它对」。 四段顺序不能换 —— 先说他关心的问题，再给东西；先讲产品，再讲过程，最后讲怎么证明。

① 用户问题30 秒

开场就说的那句 「课上老师说『下周三交实验报告』—— 这句话你记在哪儿？」

三个答案，三个都不好使：

  • 记在微信聊天记录里 → 两天后消息刷下去，找不到了；
  • 记在备忘录里 → 备忘录和课表是两回事，看课表的时候想不起还有作业；
  • 记在脑子里 → 到交作业那天才发现自己忘了。

现有工具差在哪（一句话各一个）

工具只做什么于是
超级课程表只做课表课表漂亮，但作业不在上面
滴答清单只做任务任务齐全，但看不到你明天几点有空

没有一个把这两件事放在同一个屏幕上。这就是这个项目存在的理由。

收尾那句话 「所以我做的是一个网页：打开就是『这一周』，固定课表和一次性 DDL 叠在同一根时间轴上。 打开就能看，不用注册、不用装 App。」

② 核心流程60 秒 · 现场演示，不念稿

  1. 打开链接。（会先跳一个腾讯云提示页 → 点「确定访问」。这是平台对未备案测试域名的强制提醒，不是我的页面。）
    看到：顶部「已经过期（还没打勾的）」，下面是本周 7 列 —— 课和 DDL 在同一列里，颜色不同。
  2. 点右下「+ 添加 DDL」 → 填三样：事项名称 / 截止日期 / 截止时间 → 保存。
    看到：顶部飘出 「✓ 已保存：XXX」，弹层关闭，它立刻出现在对应那一列的当天位置上。
  3. 按 F5 刷新。它还在。
    ← 这是整段演示的重点。说明数据不在这个浏览器里，在云上的数据库里。
  4. （有余力再加这一下）把链接发给旁边的人，他用自己手机打开 —— 看到的是同一份。
    这一步把「我的电脑能用」变成「别人的设备也能用」。
⚠️ 演示前必检两件事：
1. 日期要落在本周内（今天是 10/12，本周是 10/12–10/18）。填 10/20 那种下一周的日期， 一周视图里看不见它 —— 别人会以为「保存失败了」。
2. 提前访问一次，确认没被限流（短期内反复自动访问会触发「当前访问量已达上限」）。
顺手可以提一句：顶部那行小字「数据同步于 00:47」是这一周新加的 —— 数据搬到云上之后，「手机上看着不一样」「刚改完怎么没变」会真实出现，这行字就是回答「这份是什么时候取回来的」。

③ 提示词改写45 秒 · 挑一个讲，别全讲

要说清的事只有一件：同一件事，我第一遍是怎么说的，后来改成了什么，为什么改完更管用。 下面是三个真实例子，演示时挑一个讲透。

例 A（推荐）｜「怎么让 AI 不说假话」——从含糊要求，到能打勾的清单

第一遍（含糊） 「你要保证结果是对的。」「做完告诉我。」

问题：这种话 AI 有一万种方式"完成"。它可以自己判断"应该没问题"，然后回你「已完成」—— 你还没法反驳。

改写后（写进 AGENTS.md 第八节，变成四条能打勾的检查项）
  1. 这条「完成」，我实际跑过一次吗？跑的是什么命令 / 打开的是什么页面？
  2. 跑的过程里有报错、警告、异常输出吗？有的话，写出来了吗？
  3. 有没有哪部分我其实没验证？标出来了吗？
  4. 我说的「成功」，有屏幕上的证据吗（命令输出 / 页面截图 / 文件内容）？

四条里任何一条答不上来，就不是「做完了」，是「还没验证」。

为什么改完更管用：含糊的要求，AI 可以自己解释；能打勾的清单，没法糊弄。 这不是「把话说得更好听」，是把标准从形容词改成了检查项。

另外两个备选例子（想换就换）：
例 B ｜报 bug 时带上证据。「页面打不开了，你看看」→ 改成「为啥一直在加载？」+ 一张截图。 就多了那张截图，一眼看出「同步时间显示了、内容没出来」这个矛盾 → 直接指向渲染，而不是网络。
例 C ｜把「记得提交」写成固定格式。「做完记得提交」→ 改成 「commit 标题：Day 20｜一句话；说明两行：改了什么 / 加了什么」。 约束越具体，产出越稳定 —— 六周以来每天的提交记录长得一模一样。

④ 验证方式45 秒 · 我凭什么说它对

四层，从弱到强。演示时按这个顺序说，重点落在最后两层。

第 1 层 · 脚本
四套自检，一共 55 + 44 + 33 + 11 = 143 项，每次改完都重跑。 覆盖：读接口、写接口、边界（缺字段 / 格式错 / 重复）、线上文件是否与本地一致。
第 2 层 · 真浏览器
脚本只能看「文件里写了什么」，看不了「跑起来对不对」。 所以还要在真浏览器里看两件事：控制台有没有报错、界面上有没有真渲染出内容。
第 3 层 · 换个角度复核
不信脚本自己打印的「通过」，换一条路再查一遍： 不信删干净了 → 就直接问接口要数据；不信推送成功了 → 就用 API 查远端。
为什么必须有这层：这一周亲眼见过「命令跑了但没生效」—— 上传报成功、文件却传到了歪目录。
第 4 层 · 换人换设备
我自己测出来的全部结论，前提都是「我装了环境、我知道该点哪儿」。 换一个没碰过它的人、用他自己的手机，还能打开 / 还能加进去 / 没有报错 —— 这才叫成立。

收尾要说的两句话

  • 「文件传对了」≠「代码能跑」。 这一周真的踩过：33 项静态检查全绿，页面却是一片空白 —— 因为没有一项真的执行过那个渲染函数。
  • 「命令跑了」≠「命令生效了」。 退出码 0 不代表事办成了。唯一的办法是从另一个角度独立查一遍。
已知没做到的（别人问起就直说，别绕）：编辑 / 删除现在会报错 —— 那两个接口排在第 4 周，前端已经按契约写好、等接口上线就通。 这一条我在周验收表里主动标成了 FAIL，没有写成"不适用"。
