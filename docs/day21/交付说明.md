## 4. 🔴 本日最值钱的一段：一次「保存报失败、数据其实进去了」的假警报

**现象**：在公网页面点一次「保存」，界面报「保存失败：这条 DDL 已经记过了」，
**但库里确实多了一行**。这是最坏的一类 —— 界面说不成功、事实说成功。

**结论：不是产品的问题，是我的自动化工具自己造成的。**

| # | 证据 |
|---|---|
| 1 | 同一接口用 Node 直连（含带 `id` 的请求体）**稳定 200 并正确入库** |
| 2 | HAR 抓包显示整个会话里**只有 1 个 POST**，且它确实返回 409 → 客户端没重复提交 |
| 3 | 库里那行的 `id` 与那个 POST 的 `id` **对不上**，创建时间还更早 → 另有页面在发请求 |
| 4 | **清掉残留的浏览器进程后重跑**：一次点击 = 一个 POST = **200**，提示条「已保存」，库里那行 id 与请求 id **完全一致** |

**根因**：前面几轮排查反复用后台方式开浏览器，**旧会话没清干净**，两个页面各提交了一次。

> 🔑 **又一次「先怀疑测量工具，再怀疑被测对象」。** 差点就冤枉了产品。

**留下的纪律**（已记进 backlog）：跑浏览器自动化前先 `close --all`，并确认残留进程为 0。
