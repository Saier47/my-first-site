🧪 排查记录（2026-10-12 00:44 结案）——「保存报失败、数据其实进去了」是假警报。
走查时发现：在公网页面点一次「保存」，界面报「保存失败：这条 DDL 已经记过了」， 但库里确实多了一行。这是最坏的一类现象（界面说不成功、事实说成功），所以当场停下查。
结论：不是产品的问题，是我的自动化工具自己造成的。证据链 —— ① 同一接口用 Node 直连（含带 id 的请求体）稳定返回 200 并正确入库； ② HAR 抓包显示整个会话里只有 1 个 POST，且它确实返回 409（说明客户端没有重复提交）； ③ 库里那一行的 id 与那个 POST 的 id 对不上，且创建时间更早 —— 说明另有另一个浏览器页面在发请求； ④ 清掉残留的自动化浏览器进程后重跑：一次点击 = 一个 POST = 200， 提示条显示「已保存」，库里那行的 id 与请求里的 id 完全一致。
根因：前面几轮排查时用了后台方式反复开浏览器，旧会话没被清干净，两个页面各提交了一次 → 一次成功、一次 409。
又一次「先怀疑测量工具，再怀疑被测对象」 —— 这一周第三次了。 → 顺带记进待办：以后跑浏览器自动化，开之前先 `close --all` 并确认残留进程为 0。
