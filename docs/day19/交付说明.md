# Day 19 · 分层重构交付说明

> 2026-10-09 · CloudBase 环境 `my-first-site-d0g3re4p71560e327`

## 1. 今天做了什么（一句话）

**把「数据库访问」从云函数主文件里拆出来，变成独立的一层** —— 对外行为一个字没改。

## 2. 今天要掌握的那句（答案）

> **「拆完之后，『查数据库』这段代码从哪移到了哪？」**

**从 `cloudfunctions/api-func/index.js` 移到新文件 `cloudfunctions/api-func/db.js`。**

## 3. 分层的判据（比"拆成两个文件"更重要的一句）

> **「哪天换掉数据库（或换语言重写这一层），这段代码还要不要？」**
> - **要** → 它是 HTTP 的事，留在 `index.js`
> - **不要** → 它是数据库的事，搬去 `db.js`

按这个判据，**校验故意留在了 `index.js`**：
「课程名不能超过 50 字」是**业务规则**，换数据库也不变。

→ **分层是按"变化的理由"切，不是按位置切。**

## 4. 拆了什么

| | 拆前 | 拆后 |
|---|---|---|
| `index.js` | **659 行**（两件事混着）| **562 行**（只剩 HTTP 层）|
| `db.js` | —— | **255 行**（数据访问层）|

**搬进 `db.js` 的东西（6 类）**：

| 搬什么 | 它为什么属于数据层 |
|---|---|
| 数据库地址、API Key | 换数据库才知道的东西 |
| PostgREST 的 URL / `select` / `order` | 这是"怎么跟这个数据库说话"的方言 |
| `fetch` 上游 | 连库的动作 |
| `SQLSTATE 23505` 的判断 | 数据库的报错语义 |
| `newId()` | 主键生成 |
| 表结构定义（每张表有哪些字段）| 表长什么样 |

**故意留在 `index.js` 的**：路由、方法判断、读请求体、**校验**、响应信封、状态码。

## 5. 设计上的一个关键决定：`db.js` 返回"语义"而不是状态码

`db.js` 每个方法返回 `{ok:true, ...}` 或 `{ok:false, reason, ...}`，
`reason` ∈ `'CONFLICT' | 'UPSTREAM' | 'BAD_RESPONSE'`。

**为什么**：`23505` 是**数据库的知识**，不该漏到 HTTP 层去判断。
`index.js` 只想知道"这是重复还是故障"（因为两者要回不同的码：409 / 502）。

> **分层的关键不是"把代码切成两个文件"，而是每一层只暴露对方能用的词。**
