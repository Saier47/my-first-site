Day 23 · 三类错误提示（改前 → 改后）

分类标准：按「用户看到后该做什么」分，不是按状态码分 ｜ 所有「改后」均为真打线上接口的实际返回

三类怎么分

类状态码 用户该做什么文案句式
① 你的输入要改400 / 409 / 413 改一下内容再发 <哪里>不对：<为什么>。应该<怎么改>，比如「<例子>」
② 它不在了 / 没这地址404 / 405 刷新看看，或换个地址/方法 没有找到<什么>，<可能的原因>
③ 我们这边的问题500 / 502 等一会儿重试，别改输入 <哪个环节>出了问题。不是你操作的问题，过一会儿再试一次就行。
为什么第 ③ 类必须加「不是你的错」：原来的 502 写「数据库暂时读不到数据，请稍后再试」—— 用户看到这句会以为自己哪里填错了，于是反复改自己的输入、白折腾半天。 服务器的问题，就得明说是服务器的问题。

第 ① 类 你的输入要改（400）

缺必填字段 · POST /api/courses {}
现状
缺少必填字段 name（课程名），比如「高等数学」
这一条本来就达标了 —— 列出它作为标杆：好提示长什么样。
星期几超范围 · { day_of_week: 9 }
现状
day_of_week（星期几）必须是 1 到 7 的整数（1 = 周一），你给的是「9」
两个要点：说清合法范围 + 回显用户给的值（他知道自己错在哪）。
请求体太大 · 413
改前
请求内容太大了（超过 64KB），请检查是不是发错了东西
只说"太大了"，没说正常应该是多大，用户无从判断。
改后
发过来的内容太大了（超过 64KB）。课表一条记录最多几百字节 —— 多半是误把整个文件贴进来了，请只发这一条数据
给了量级参照（几百字节 vs 64KB）和最可能的原因。

第 ③ 类 我们这边的问题（500 / 502）— 今天改的重点

读数据时上游挂了 · 502
改前
数据库暂时读不到数据，请稍后再试
用户会想："是不是我哪里点错了？"—— 于是去改自己的操作，白折腾。
改后
我们这边出了点问题：数据库暂时读不到数据。不是你操作的问题，过一会儿再试一次就行。
明确不是你的错 + 告诉他只要等一会儿，不用改任何东西。
写入 / 修改 / 删除时上游挂了 · 502 ×3
改前
数据库暂时写不进去 / 改不了 / 删不了，请稍后再试
改后
我们这边出了点问题：数据库暂时写不进去。不是你操作的问题，过一会儿再试一次就行。
未捕获异常 · 500
改前
服务内部出错了，请稍后再试
"服务内部出错"是说给开发者听的；而且出了问题没有编号，用户报故障时说不清是哪一次。
改后
我们这边出了点问题：处理这次请求时出错了。不是你操作的问题，过一会儿再试一次；如果一直这样，把这串编号发给管理员：req_xxxxx
加了请求编号 —— 用户能报出来，我们才查得到是哪一次。
服务端配置缺失 · 500
改前
服务端没有配置数据库密钥，请联系管理员检查云函数环境变量
"环境变量"是给运维看的词，用户看不懂；也没给请求编号。
改后
我们这边出了点问题：服务端还没配好数据库密钥。这不是你操作的问题，已经记下来了，稍后会自动恢复；如果一直这样，把下面这串编号发给管理员：req_xxxxx
一致性怎么保证的：这 7 条 502 的「不是你的错」不是各写一遍 —— 抽成了两个常量 WE_ARE_SORRY_PREFIX / WE_ARE_SORRY_SUFFIX。 以后改一次、全生效，不会出现"有一条忘了带"的情况。

保持原样 第 ② 类：已经是好文案

删不存在的记录 · 404
现状
没有找到 id 为「xxx」的记录，可能已经被删掉了
回显了 id + 给了合理的解释。
用错方法 · 405
现状
路径 /api/courses 只支持 GET（读全部）和 POST（新建）。要改或删某一条，请带上它的 id：/api/courses/<id>。你用的是 PUT
说清支持什么 + 你想做的动作该打哪个地址 + 你实际用的是什么。三条齐全。
为什么第 ② 类没动：它已经满足"说清下一步能干嘛"的标准了。 统一 ≠ 全部重写 —— 把已经合格的东西改一遍，只会引入新风险。
