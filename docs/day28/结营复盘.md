> 今天那题：**28 天里你最大的一个认知改变是什么？**

---

## 一、我的答案

> **从「我做完了」变成「我证明它真的能用了」。**

说得再具体一点：

**第 1 周我以为的"完成"** ＝ 代码写出来了、本地能跑、我读过一遍觉得没问题。
**第 4 周我认的"完成"** ＝ 有一个**我没参与过的动作**，从一个**我没控制的入口**，
证明它真的能用 —— 而且这个证明要**留下证据**。

**中间隔着的，是 28 天里 8 次翻车。**

## 二、八次翻车，一个形状

| Day | 我以为 | 实际 | 差在哪 |
|---|---|---|---|
| 6 | 功能写完了 | 没有"验证过"的记录 | 缺一道**验收动作** |
| 10 | 操作成功了 | 结果**消失了**（读写不同源） | 成功了 ≠ 生效了 |
| 13 | 骨架屏 7 格，数量对 | 实际是**纵向 1 列** | **数量对 ≠ 布局对** |
| 20 | 33 项静态检查全绿 | **页面根本打不开** | 检查覆盖不到真运行 |
| 20 | 部署命令退出码 0 | 文件传到了**歪目录** | 命令跑了 ≠ 生效了 |
| 23 | 密钥扫描"0 命中" | 8 条规则里**3 条是坏的** | 尺子坏了，0 命中是假的 |
| 24 | 点了删除 | 界面**一个字都没说** | 沉默 = 用户以为点偏了 |
| 25 | 检查全绿 | 检查器自己会**假绿 / 假红** | 检查也要被检查 |

**八次，八种样子，同一个形状**：

> **「我以为的」和「实际发生的」之间，永远有一道缝。**
> 而且**每次都是缝先被发现，我才知道那里有缝**。

**最要命的是**：这八次里，**没有一次是"功能没写"**。
代码都是在的、逻辑都是对的 —— 死的全是**"我以为它好了"**。

## 三、这条认知具体改变了什么

不是变"谨慎"，是变**具体**。落到手上的四条：

| 以前 | 现在 |
|---|---|
| 命令行说成功 = 成功 | **从另一个角度独立查一遍**（推送 → 问 GitHub API 要 SHA；部署 → 拉线上文件比对） |
| 我读过代码 = 没问题 | **让现象先说话**（列假设 → 逐个真做一次排除 → 再看代码） |
| 检查全绿 = 没事 | **故意弄坏一项，看它红不红、红得准不准** |
| 用户没反馈 = 没事 | **沉默本身就是症状**（Day 24 那个 Bug 就是这样） |

**第 3 条是 28 天里最晚学会、也最贵的**：
一个**永远输出 ✅ 的检查**，和**真的全绿**，在屏幕上长得一模一样。
所以判断一个检查有没有用，**不能看它平时绿不绿，要看它被弄坏时会不会红**。
